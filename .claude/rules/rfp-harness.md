# RFP 실행 하네스

이 사업의 코드·설정·테스트를 생성할 때 지켜야 할 규칙이다. 공공 SW사업 제안요청서(RFP)의 상세 요구사항 분류체계·작성 품질 기준·추적성·사업관리 요구사항을 이 사업에 맞춰 적용한 것이다.

**사업명** — 생활체육 경기 영상을 멀티모달로 분석하여 용병을 구인하고 RAG 검증을 자동화하는 플랫폼
**기간** — 2026-08-20 ~ 2026-10-27 (10주, 5스프린트)

## 0. 이 문서의 위치

**요구사항의 원본은 이 문서가 아니라 보고서다.**

| 무엇 | 어디 |

이 문서는 그 요구사항을 **코드로 옮길 때의 규칙**만 담는다. 요구사항 자체를 여기서 새로 만들거나 바꾸지 않는다. 설계가 바뀌면 보고서의 해당 장을 먼저 고치고 이 문서를 따라 맞춘다. 두 곳이 어긋나면 **보고서가 맞다.**

## 1. 필수 준수 규칙

### 1.1 명확성 — 측정 가능한 표현만 쓴다

모호한 서술을 코드 주석·문서·커밋 메시지에 남기지 않는다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| "빠르게 처리한다" | "후보 목록 요청부터 순위 표시까지 NFR-01 목표 이내" |
| "정확도를 높인다" | "Recall@5 90% 이상 (NFR-03)" |
| "안정적으로 저장한다" | "스탯 변동마다 근거 장면 식별자를 함께 저장한다 (FR-34)" |

### 1.2 원자성 — 요구사항 ID 하나가 독립 검증 단위다

하나의 요구사항이 여러 모듈에 걸치면, 모듈마다 그 ID를 명시하고 각각 독립적으로 검증 가능하게 나눈다. 두 요구사항을 한 함수에 섞지 않는다.

### 1.3 추적성 — 모든 산출물에 요구사항 ID를 남긴다

생성하는 모든 소스·테스트·설정 파일 상단에 관련 요구사항 ID를 주석으로 적는다.

```python
# Requirement: FR-33, NFR-03
# Verifies: TC-34, TC-35, NT-03
```

```typescript
// Requirement: FR-22
// Verifies: TC-23, TC-24
```

```sql
-- Requirement: FR-34, NFR-05
```

- `Requirement` — 이 파일이 구현하는 요구사항 ID (2장)
- `Verifies` — 이 파일이 통과해야 하는 시험 항목 ID (7장). 테스트 파일에는 필수다

ID가 없는 파일은 리뷰에서 반려한다. 요구사항에 없는 기능을 만들고 있다면 그것이 신호다 — 코드를 쓰기 전에 2장에 요구사항을 먼저 추가한다.

### 1.4 검증성 — 검수 기준을 테스트로 만든다

기능 코드를 생성할 때 대응하는 시험 항목(TC)의 테스트 코드를 **함께** 만든다. 나중에 붙이지 않는다. 7장의 판정 기준 문장이 그대로 테스트의 단언이 되어야 한다.

### 1.5 미확정 값을 지어내지 않는다 — 이 사업 고유 규칙

보고서 본문에는 `〔확인 필요: …〕`로 표시된 미확정 값이 있다.

```bash
grep -rn '〔확인 필요' *.md
```

**이 값들을 임의로 채워 코드에 넣지 않는다.** 프레임 추출 간격, 식별 신뢰도 임계, 스탯 변동 폭 상한, 실력 등급 구간, 비기능 목표치가 여기에 해당한다. 그럴듯한 기본값을 넣으면 결정된 값처럼 굳어 버린다.

대신 아래처럼 처리한다.

1. 설정 파일이나 상수로 **바깥에 빼고**, 값 자리에 미결 표시를 남긴다.
2. 해당 값에 의존하는 테스트는 목표치를 하드코딩하지 않고 설정을 읽는다.

```python
# Requirement: NFR-04
# TODO(미확정): 스탯 변동 폭 상한. 6장 〔확인 필요: 가중 감쇠 기간〕과 함께 확정한다.
STAT_DELTA_MAX = None  # 확정 전까지 None. 호출부는 None이면 갱신을 보류한다.
```

### 1.6 근거 없는 판정을 만들지 않는다 — 이 사업 고유 규칙

검증 경로의 코드는 **근거 장면 없이 판정 결과를 반환하거나 저장할 수 없어야 한다.** 6장 2절의 설계이자 이 사업의 핵심 규칙이다.

- 검증 에이전트 응답에 근거 식별자가 비어 있으면 서버는 저장하지 않는다 (TC-35).
- 판정 레코드가 근거 장면을 참조하지 않으면 저장 단계에서 거부한다 (3장 데이터 모델).
- 검색 결과가 비었을 때 모델이 일반 추론으로 답을 만들지 않도록 프롬프트에 `판정 불가` 반환을 명시한다 (4장 4절).

## 5. 태스크 지시문

각 태스크는 확정 사항(2절)이 갖춰진 뒤에만 실행한다.

### Task 1 — 저장소 스키마

> 확정 사항: 데이터 저장소 ✅

3장의 엔터티 목록대로 Aurora PostgreSQL 스키마를 만든다. 아래 네 가지를 스키마 수준에서 강제한다.

1. 역할은 사용자가 아니라 **참여**에 붙는다.
2. 스탯 항목은 **정의 테이블**을 참조한다 (NFR-05).
3. 스탯은 **현재값과 변동 이력을 분리**하고, 변동마다 근거를 남긴다.
4. 검증 판정은 **근거 장면을 참조하지 않으면 저장할 수 없다** (제약으로 표현).

벡터 컬럼은 `pgvector`를 쓰고, 색인 종류와 파라미터는 측정 후 결정한다.

### Task 2 — 영상 색인 파이프라인 (FR-32)

2단계 프레임 추출을 구현한다. 1차로 넓은 간격·저해상도로 구간을 추리고, 2차로 추려진 구간만 좁은 간격·고해상도로 분석한다. **추출 간격과 해상도는 설정으로 빼고 하드코딩하지 않는다** (1.5절).

식별 신뢰도가 임계 미만인 장면은 색인은 하되 스탯 산출 대상에서 제외한다 (TC-33).

### Task 3 — 근거 검색·판정 (FR-33, NFR-03)

검색 후 판정 경로를 만든다. 검색 결과가 비면 `판정 불가`를 반환하고, 서버는 근거 식별자가 없는 판정을 저장하지 않는다.

같은 태스크에서 **Hit Rate·Recall@5 측정 코드**를 함께 만든다. 정답 근거 집합을 입력으로 받아 두 지표를 출력하는 형태이며, 목표치는 설정에서 읽는다.

### Task 4 — 매칭 (FR-22, FR-23)

순위 요소의 수치화는 서버에서 계산해 에이전트 입력으로 넘긴다. 가중치를 모델이 정하게 하지 않는다. 에이전트 출력은 스키마로 고정하고, 스키마를 벗어난 응답은 반영하지 않는다 (TC-24).

조건 완화가 적용되면 완화 항목을 응답에 포함한다 (TC-25).

## 6. 검증 체크리스트

작업을 마쳤다고 보고하기 전에 스스로 확인한다.

- [ ] **추적성** — 생성한 모든 파일 상단에 `Requirement:` 주석이 있는가. 테스트 파일에는 `Verifies:`도 있는가
- [ ] **검증성** — 구현한 FR마다 대응 TC의 테스트가 함께 있는가
- [ ] **미확정 값** — 〔확인 필요〕 값을 임의로 채운 곳이 없는가. 설정으로 빠져 있는가
- [ ] **근거 규칙** — 근거 없이 판정이 저장될 수 있는 경로가 없는가
- [ ] **NFR-05** — 종목·포지션·스탯 항목이 코드 상수로 박혀 있지 않은가
- [ ] **NFR-06** — 로그·응답에 좌표나 식별자가 노출되지 않는가
- [ ] **환경 변수** — 새로 필요한 키를 [`.env.example`](../../.env.example)에 추가했는가. 실제 값을 커밋하지 않았는가
- [ ] **문서 동기화** — 설계가 바뀌었다면 보고서 해당 장을 같은 스프린트 안에 고쳤는가

```bash
# 추적성 누락 검사 (예시)
grep -rLn 'Requirement:' services/ apps/ --include='*.py' --include='*.ts'
```

## 7. 사업관리 요구사항 (PMR)

[제 8 장](../../08-schedule.md)이 원본이다. 코드 작업과 맞닿는 부분만 옮긴다.

| 항목 | 규칙 |
|---|---|
| 완료 조건 | ① 담당 외 1인 리뷰 통과 ② 대응 TC 통과 ③ 설계 변경 시 문서 반영 — 셋을 모두 만족해야 `완료` |
| 리뷰 | 담당 영역 밖의 인원이 한다 (8장 교차 리뷰 표) |
| 승인 | 작업당 승인자는 한 사람이다 (8장 책임 배분표) |
| 진척 기록 | 스프린트별 일자 기록에 **실제로 한 작업**을 남긴다. 계획을 옮겨 적고 완료로 표시하지 않는다 |
| 위험 | `R-01`~`R-08`. 새 위험이 보이면 8장 3절에 추가한다 |

**기간은 고정 조건이다.** 일정이 밀리면 기간이 아니라 범위를 줄이고, 줄인 항목은 [제 9 장](../../09-conclusion.md) 3절에 남긴다.
